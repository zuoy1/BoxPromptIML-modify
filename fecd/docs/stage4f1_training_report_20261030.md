`L = mean_image(0.5 × mean_selected_positive_BCE + 0.5 × mean_selected_negative_BCE)`。

## 8. 开发集评估协议

固定评估 `new_dev` 的 530 张图，共 233 个来源代理组。输入 RGB 以 PIL BILINEAR 缩放到 224×224，并做 ImageNet mean/std 归一化；无评估增强。GT 使用已验证的二值 0/255 mask，NEAREST 缩放到 224×224 后 `>127` 二值化。指标是在该 224×224 网格上计算，不能写成原始分辨率边界精度。

预测使用 **raw logits → sigmoid → threshold ≥ 0.5**，不做逐图 min-max 归一化。batch size=1；每图恢复 checkpoint 的 memory 状态，以避免模型可变 memory 状态把前一张图带入后一张。每组 memory gate 的重复、倒序、冷模型、磁盘 checkpoint 不变、snapshot 不变检查均记录 PASS；这些具体 gate 只用了两张 RGB 样本，不代表对 530 张图的全部排列进行了测试。

image-macro F1/IoU 先逐图计算再平均；pooled micro 合并 TP/FP/FN 后计算；dataset-equal 先求四个域各自的 image-macro，再等权平均。空预测与空 GT 同时出现时 F1/IoU 定义为 1，仅一方为空时为 0。

原始旧版 eval 的 min-max 口径与本严格协议不同，不应直接拼表归因。

## 13. 最终验收失败的详细诊断

### 13.1 原始失败位置

`logs/validation.log` 显示 `fecd/tools/check_stage4f1.py:72` 执行以下断言失败：

```python
assert abs(step['loss'] - step['pos_contribution'] - step['neg_contribution']) < 1e-7
```

验收按 P0→P1→P2F→P3F 顺序检查；原始调用在 P0 中止，后面完整验收逻辑没有跑完，运行目录中没有成功的 `artifacts/validation.json`。不能把尚未执行到的检查视为已通过。

### 13.2 本次对全部正式更新的只读复核

| 组别 | 正式步骤数 | 残差≥1e-7步数 | 最大绝对残差 | 不符合float32加法步数 | NaN/Inf步骤数 |
| --- | --- | --- | --- | --- | --- |
| P0 | 17660 | 1 | 1.043081283569336e-07 | 0 | 0 |
| P1 | 17660 | 0 | 8.940696716308594e-08 | 0 | 0 |
| P2F | 17660 | 0 | 5.960464477539062e-08 | 0 | 0 |
| P3F | 17660 | 2 | 1.192092895507812e-07 | 0 | 0 |

第一个原始失败点：**P0 / epoch 17 / epoch内 update 15 / 累计 update 14143**。

- 已记录 loss：`2.0073587894439697`。
- 正类贡献：`1.8338468074798584`。
- 负类贡献：`0.17351208627223969`。
- Python float 下残差：`1.043081283569336e-07`，刚超过固定阈值 `1e-7`。

训练的 `class_balanced_masked_bce` 在 float32 tensor 上先相加，然后分别把 loss、正类贡献、负类贡献转为 Python float 写入 JSON。重新用 Python float 相加两个贡献，和训练中的 float32 相加舍入路径不同。在该样本 loss≈2.00736 时，相邻 float32 数的间隔约为 `2.384185791015625e-7`，固定 `1e-7` 比半个间隔还小，合法舍入即可触发断言。

本次逐步重算 `float32(pos_contribution + neg_contribution)`，**四组全部 70,640 步都与保存 loss 完全相等**，且 epoch mean loss 与逐步算术平均一致。这比仅推测“可能是浮点问题”更直接地支持精度口径诊断，但不构成对所有其他验收条件的替代。

### 13.3 应如何处理

建议后续针对验收器精度口径做最小修复：保留真实损失分解校验，在与训练一致的 float32 加法语义下核对，或使用有依据、随数值规模与 dtype 变化的误差界；同时用超过合理误差的反例确认真实损坏仍会被拒绝。不要修改历史日志来凑断言，也不要无依据大幅放宽容差。

修复后还需重新运行完整验收，检查其余身份、选择集合、访问边界、哈希和统计。**本报告仅提出建议，没有修改任何训练或验收代码，没有改 `status.json`，也没有重跑训练。**
